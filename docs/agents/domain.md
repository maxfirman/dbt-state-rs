# Domain docs

Before domain exploration or design, read root `GLOSSARY.md` and the relevant
ADRs in `docs/adr/`. Create these files as terms or decisions are resolved if
they do not yet exist.

Use glossary terms consistently in issues, designs, hypotheses, and tests.
Surface conflicts with existing ADRs explicitly before proposing a change.
Keep term definitions in the glossary and decision rationale in ADRs; current
implementation and validation details belong in the linked technical docs.
